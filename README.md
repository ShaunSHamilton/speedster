# Speedster

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)

A tray app that runs an internet speed test on a schedule and keeps the history on your machine:

- **Download, upload, latency, jitter** - measured against `speed.cloudflare.com`, or the Ookla `speedtest.exe` if you point it at one.
- **Bytes transferred** - every result records exactly how much data the test spent, so you can see the cost of the monitoring itself. A default test costs about 4 - 5 MB, because it measures for a target number of seconds rather than pulling a fixed pile of bytes.

Data-plan aware: it skips metered connections by default, and can be pinned to a list of networks (Wi-Fi SSIDs) so it never tests on a hotspot. Pause is one click.

Everything is plain text under `%LOCALAPPDATA%\Speedster` - a CSV log and an INI file, both readable and editable by hand. Nothing is uploaded anywhere; the only traffic Speedster generates is the test itself. No install, no admin, no SDK.

## Quick Start

1. Download **[Speedster.exe](https://github.com/ShaunSHamilton/speedster/raw/master/Speedster.exe)** and put it anywhere (for example `%LOCALAPPDATA%\Programs`).
2. Run it - a coloured circle appears in the tray showing the last download speed.
3. Right-click it -> **Start with Windows**, and set **Frequency** to taste.

The first test runs 60 seconds after launch, then every `interval_minutes`.

## Usage

| Item                      | Effect                                                                                                                 |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Status lines              | `8.2 Mbps down · 2.5 up · 23 ms`, then the timestamp, bytes moved and current schedule                                 |
| **Run test now**          | Test immediately, off-schedule                                                                                         |
| **Open report**           | Regenerate `report.html` and open it in the default browser                                                            |
| **Pause**                 | Stop the schedule; icon turns amber. Click again to resume                                                             |
| **Frequency**             | 5 min ... 1 day, or **Custom...** for any number of minutes                                                            |
| **Networks**              | Current network name, **Run on any network**, **Only run on "SSID"**, and the allow-list (click an entry to remove it) |
| **Skip metered networks** | Refuse to test when Windows reports the connection as metered, over its data limit, or roaming                         |
| **Engine**                | `Cloudflare (built-in)` or `Ookla CLI` (enabled once `ookla_path` is set)                                              |
| **Start with Windows**    | Adds/removes `Speedster` under `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`                                    |
| **Open data folder**      | Opens `%LOCALAPPDATA%\Speedster`                                                                                       |

Icon colour: green = have a result, blue = testing, amber = paused, grey = nothing logged yet. Left-click refreshes the network state, double-click opens the report.

Only one instance runs at a time (a named mutex); launching a second one exits silently.

## Data

`%LOCALAPPDATA%\Speedster` holds four files, all plain text:

| File            | Contents                                                                                                                         |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| `results.csv`   | One row per test: `timestamp_utc,down_mbps,up_mbps,latency_ms,jitter_ms,down_bytes,up_bytes,network,metered,engine,server,error,down_seconds,up_seconds` |
| `settings.ini`  | `key=value`, comments on their own line. Edited by the menu, safe to edit by hand                                                |
| `report.html`   | Generated by **Open report**; self-contained, works offline                                                                      |
| `speedster.log` | Rolling diagnostics, truncated at 256 KB                                                                                         |

`down_seconds`/`up_seconds` are the window each rate was measured over, so a short - and therefore less certain - sample is visible rather than implied.

Skipped runs are logged too, with empty metrics and `error=skipped: metered` or `skipped: network not allowed`, so gaps in the chart are explained rather than silent. A direction that transferred nothing is recorded as `error=download failed: ...`, never as `0 Mbps`.

### `settings.ini`

Every knob below is a plain key in the file. Values outside the listed range are clamped on load - the bounds exist to stop a typo producing a hung or runaway test, not to second-guess a deliberate choice.

| Key                            | Default      | Range           | Meaning                                                            |
| ------------------------------ | ------------ | --------------- | ------------------------------------------------------------------ |
| `interval_minutes`             | `60`         | 1 - 525600      | Schedule cadence                                                   |
| `paused`                       | `false`      |                 | Suspend the schedule                                               |
| `engine`                       | `cloudflare` |                 | `cloudflare` or `ookla`                                            |
| `ookla_path`                   | _(empty)_    |                 | Full path to `speedtest.exe`                                       |
| `skip_metered`                 | `true`       |                 | Never test on a metered connection                                 |
| `only_networks`                | _(empty)_    |                 | Comma-separated network names; empty means any                      |
| `target_seconds_down`          | `3`          | 0.1 - 3600      | Download stops after this much transfer                            |
| `target_seconds_up`            | `3`          | 0.1 - 3600      | Upload stops after this much transfer                              |
| `max_bytes_down`               | `6000000`    | 50 KB - 100 GB  | Download data ceiling, split across streams                        |
| `max_bytes_up`                 | `3000000`    | 50 KB - 100 GB  | Upload data ceiling, split across streams                          |
| `streams`                      | `4`          | 1 - 64          | Concurrent connections per direction                               |
| `max_test_seconds`             | `20`         | 1 - 3600        | Absolute per-direction guard against a stalled transfer            |
| `discard_ms`                   | `500`        | 0 - 600000      | Minimum opening of the window dropped as slow start                |
| `discard_percent`              | `25`         | 0 - 90          | Drop this share of the window instead, when it is larger           |
| `min_window_ms`                | `1200`       | 0 - 3600000     | Below this total window, discard nothing - there is none to spare  |
| `sample_ms`                    | `100`        | 10 - 60000      | Throughput sampling resolution                                     |
| `latency_samples`              | `12`         | 1 - 1000        | Timed round trips per test, excluding the warm-up                  |
| `read_buffer_bytes`            | `65536`      | 1 KB - 8 MB     | Download read size; smaller stops nearer `target_seconds`          |
| `write_chunk_bytes`            | `65536`      | 1 KB - 8 MB     | Upload write size; smaller stops nearer `target_seconds`           |
| `request_bytes_max`            | `25000000`   | 100 KB - 90 MB  | Ceiling on one HTTP request; a stream issues as many as it needs   |
| `retry_count`                  | `2`          | 0 - 10          | Retries when the server throttles (403/429), halving size each try |
| `retry_delay_ms`               | `1000`       | 0 - 60000       | Pause before a retry                                               |
| `run_on_startup_delay_seconds` | `60`         | 0 - 86400       | Grace period after login                                           |
| `last_run`                     | _(written)_  |                 | ISO-8601 UTC; the schedule survives restarts                       |

The pre-2026-07 keys `target_bytes_down`/`target_bytes_up` are still read, as `max_bytes_down`/`max_bytes_up`.

**Data cost.** Each direction stops at whichever arrives first, `target_seconds_*` or `max_bytes_*`. On a slow link time wins and the test is cheap; on a fast link the byte ceiling wins. On a ~9 Mbps line the defaults cost **4 - 5 MB per test** (about 3 GB/month hourly); the ceiling makes the worst case 9 MB. The report's **Projected / month** tile shows the figure for your own settings and measured speeds.

Raise `target_seconds_*` for a steadier reading on a noisy link, or raise `max_bytes_*` on a fast one - at 500 Mbps the 6 MB download ceiling is only ~100 ms of transfer, which no estimator can make as trustworthy as a full 3 s window.

## Report

**Open report** writes `report.html` and opens it. It contains median/min/max download, upload and latency for the selected range, the test and skip counts, cumulative bytes and a monthly projection, a throughput chart, a latency chart, and the last 50 rows as a table. Hovering a point shows that test's bytes and the window it was measured over. Range presets are 24 hours / 7 days / 30 days / all. It follows the system light or dark theme and needs no network access to render.

## Uninstall

1. Right-click the tray icon -> uncheck **Start with Windows** -> **Exit**.
2. Delete `Speedster.exe`.
3. Delete `%LOCALAPPDATA%\Speedster` if you do not want to keep the history.

## Building from source

Requires nothing but Windows - it builds with the in-box .NET Framework compiler.

```powershell
git clone https://github.com/ShaunSHamilton/speedster
cd speedster
.\build.ps1
```

`Speedster.exe` lands in the repo root. `portal.html` is embedded into the exe as a resource, so edit it and rebuild to change the report.

## How it works

- Schedule: a 30-second `System.Windows.Forms.Timer` compares `UtcNow` against `last_run + interval_minutes`, so sleep, hibernate and restarts cannot make the cadence drift. `SystemEvents.PowerModeChanged` (resume) and `NetworkChange.NetworkAddressChanged` re-check immediately.
- Network name: `INetworkListManager.GetNetworks` -> `INetwork.GetName()`. Windows names wireless networks by SSID, so the allow-list keys off the SSID without parsing `netsh` output.
- Metered state: WinRT `NetworkInformation.GetInternetConnectionProfile().GetConnectionCost()`, reached by reflection (`ContentType=WindowsRuntime`) because the compiler cannot consume `.winmd`. Metered means cost type `Fixed`/`Variable`, over the data limit, or roaming.
- Latency: `latency_samples` timed `GET /__down?bytes=0` requests over one kept-alive connection, minus Cloudflare's own `Server-Timing` durations - which lands within about 1 ms of the TCP `min_rtt` the edge reports. The reported figure is the minimum; jitter is the mean absolute difference between consecutive samples. The warm-up request is excluded, and it leaves a connection with a grown congestion window for the transfers that follow.
- Throughput: `streams` concurrent `GET /__down?bytes=N` and `POST /__up`, stopping at `target_seconds` or `max_bytes`. Every byte is counted as it moves, so `down_bytes`/`up_bytes` are what was really transferred - but the rate is computed only over the window that survives dropping `max(discard_ms, discard_percent)` of the opening, because that opening is TCP slow start and reads low. Measured on a 9 Mbps line: a 1 MB sample and an 8 MB sample of the same transfer agree within 2%, while averaging across a full 12 MB run read 20% low because a mid-transfer stall got included. Time in steady state is what makes the number valid; bytes are only its cost.
- Throttling: the test server answers 403/429 once a client has pulled a lot in a short window. A throttled request is retried `retry_count` times at half the size; a direction that still moves nothing is logged as a failure rather than as `0 Mbps`.
- Tray icon: drawn at runtime with GDI+ (`Bitmap.GetHicon`, then `DestroyIcon` to avoid leaking the handle), so there is no icon resource to ship.
